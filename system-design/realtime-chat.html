Case Study 03

Real-Time Chat

The project uses Laravel Reverb, Laravel Echo, private presence channels, typing indicators, seen status, message history and CI. Here the main design challenge is different: WebSocket connections stay open, while messages still need durable storage and authorization.

Correct order

Persist the message before broadcasting so the real-time event is backed by durable history.

Connection cost

WebSockets use long-lived connections, so server capacity is affected by connected users even when they are not sending messages.

Authorization

Private channels and conversation policies prevent clients from subscribing to conversations they do not own.

Why split

HTTP requests and persistent socket connections have different resource patterns, so they can scale independently.

Presence state

Shared Redis-backed state helps multiple realtime nodes agree on online users and queued broadcasts.

History

Paginate older messages and index conversation_id + created_at rather than loading entire conversations.

Partition naturally

Route conversations or users consistently so connection state is easier to distribute across socket nodes.

Delivery semantics

Use message IDs, acknowledgements and retry-safe logic when delivery reliability matters.

Protect storage

Cache presence and transient typing state; do not write every ephemeral signal to the main database.
